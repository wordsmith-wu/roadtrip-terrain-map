# 地点当天的天气：数据、静态图标与避让

仅在用户要求天气时使用。保留原路线、地形与里程；样式迭代复用同一天气快照，不悄悄刷新数据。

## 日期与快照

- 天气需要完整年月日。逐日行程没有年份时询问，或采用用户已明确确认的年份；不能照搬新疆示例的 2026 年。只有 D1/D2 时先补全日期。
- 获取数据前核对服务当前覆盖范围。未来超出预报时限标“暂无预报”；过去日期使用历史数据并明确其类型，不把历史再分析称作实测，也不把旧预报称作当天实况。旧图若保留旧预报，注明快照日期。
- 保存 source、source_url、retrieved_utc、timezone、data_kind（forecast / historical / archived_forecast）和 records。每条记录关联稳定地点 ID、坐标、完整日期、weather_code、temperature_2m_min/max；单位为 °C。记录所用天气代码标准，不能跨服务直接套用代码表。
- 以地点 ID + 日期去重。同一地点不同日期保留多行；同日往返不重复天气。缺失温度或代码显示“暂无数据”，不能把 null 格式化为数字，也不能用晴天作默认值。
- 使用来源许可允许的图标/字体，并保留天气来源署名；不打包系统商业字体。

## 静态显示

图片优先采用与网页相同语义的彩色天气 emoji，例如晴 ☀️、多云 ⛅、雨 🌧️；不是网页截图。默认每行“09/24  图标  12–23°C”，不用大卡片盖住地形。网页悬浮可作为额外交付，但不能代替 PNG/SVG 中的天气。

先检测本机彩色字体和 Pillow 彩色渲染能力。Windows 案例使用 Segoe UI Emoji；其他平台需选择可用字体及其支持的像素字号，或使用获授权的透明图标资产。缺字方框/单色退化不能悄悄交付。

### 已验证的裁切故障

Pillow 配合 Segoe UI Emoji 的 `anchor='mm'` 曾导致太阳、云朵的彩色层被裁掉；增大画布或提高图层都未解决。模板改为在带留白的画布上按默认原点绘制，再按 alpha 包围盒裁切：

```python
canvas = Image.new('RGBA', (256, 256))
ImageDraw.Draw(canvas).text((40, 40), glyph, font=emoji_font,
                           embedded_color=True)
bounds = canvas.getbbox()
assert bounds and 0 < bounds[0] < bounds[2] < canvas.width
assert 0 < bounds[1] < bounds[3] < canvas.height
icon = canvas.crop(bounds)
```

该尺寸针对示例的 96 px 字体；换字体/字号需重新测量。边界断言仅能发现画布边缘溢出，不能证明彩色层完整，仍需查看实际太阳、云朵、雨雪图标。不要再次使用居中 anchor 来“修复”定位。

## 整组避让与验收

1. 完成画布、字号、投影后 draw，获取实际 renderer。先布局地名与天气文本，再放图标。可保留图标槽位，但槽宽必须按真实字体测量，不能猜几个空格就足够。
2. 同时测量日期宽、槽宽、行高；图标保持纵横比，最大边受槽宽和行高共同限制。单位统一为 points 或显示像素，检查导出 DPI 下的转换。
3. 地名、全部天气行、图标作为同一标签组避让，考虑里程标签、邻近地名、路线和局部图边界。密集区换偏移/引线或放大局部图，不移动地理点；必要时扩大画布。贪心算法找不到空位要报告并调整，不能只把冲突得分最小的结果当作通过。
4. 图标位于地形、路线和文本底板之上，但 zorder 只能修正层级，不能解决图标与文字的重叠。固定位置图标需在文本最终排版之后生成。
5. 检查 PNG 及 SVG，查看全图和密集区域原始分辨率裁切，确认太阳为完整圆形、云朵/雨雪完整、日期温度不被覆盖。覆盖晴、多云、雨雪和缺数据用例。

示例使用 Matplotlib 私有 `_get_layout` 提取行位置，其结构依版本变化；迁移时优先采用独立文本对象或公开布局组件。如保留该调用，记录版本并验证返回结构，不能盲抄索引。

里程标签显示 `Dn · 1,234.5 km`，仅删除“累计”字样，累计算法和数值不变。脚注仍可说明累计语义和未计算路段。
